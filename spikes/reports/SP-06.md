# SP-6: swarm handoffs with `Command(graph=Command.PARENT)`

Script: `spikes/test_sp06_swarm.py` (4 checks, all pass). The swarm is a graph whose member nodes each invoke a `create_agent` graph; handoff tools use `InjectedState` and `InjectedToolCallId` and return `Command(goto=<member>, graph=Command.PARENT, update={"messages": [...], "active": ...})`. A root node invokes the swarm.

| Question | Result |
|---|---|
| Handoff raised by a tool inside an agent graph invoked in a member node | Routes the **swarm** graph to the target member |
| Shared history | The target member sees human message, the handoff `AIMessage` and the `ToolMessage`; no dangling tool call |
| Interrupt inside a member (HITL on a handoff tool) | Pauses the whole run; resume approves the handoff and the run finishes. The interrupted member's model turn is not repeated. |
| Step limit | `recursion_limit` on the swarm invocation stops endless handoffs with `GraphRecursionError` after exactly `limit` member turns (5 → 3 + 2; 11 → 6 + 5) |

**Conclusion:** the design holds. The swarm's `maxSteps` maps to the swarm invocation's `recursion_limit` (one member turn per superstep), and the swarm node turns `GraphRecursionError` into `LOOP_LIMIT_EXCEEDED`. The fallback (members added directly as subgraph nodes) is not needed.
