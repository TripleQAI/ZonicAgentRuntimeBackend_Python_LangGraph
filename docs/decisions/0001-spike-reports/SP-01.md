# SP-1: `Command` joins, `defer`, superstep overhead, recursion limit

Script: `spikes/test_sp01_command_joins.py` (13 checks, all pass). Run on 2026-10-25 with LangGraph 1.2.17, Windows, 28 CPUs.

| Question | Result |
|---|---|
| Two nodes in one superstep both `Command(goto="join")` | `join` runs once |
| Static edge and `Command` to the same target in one superstep | `join` runs once |
| Unequal branches without `defer` | `join` runs twice, once per arrival. A join after branches of different length needs a barrier. |
| `defer=True` on a `Command`-triggered join | Runs once, after the longest branch. It also works inside a loop (once per round, 3 rounds). |
| What `defer` waits for | Every pending task of the graph run, including branches that never reach the join. It is a run-level barrier. |
| List-form edge `add_edge(["a", "b2"], "join")` | Waits for exactly its sources; an unrelated branch keeps running. With an untaken source (exclusive branch) it never fires. |
| Overhead per superstep, 400-step loop, best of 3 | No checkpointer 202 µs; `durability="exit"` 203 µs; `"async"` 254 µs; `"sync"` 253 µs |
| Installed default recursion limit (DR-13) | 10,007, overridable by `LANGGRAPH_DEFAULT_RECURSION_LIMIT` |

**Conclusion:** the design holds. `Command` routing joins without duplicates, and `defer` joins branches of unequal length. One caveat: `defer` is run-scoped. In a graph where a join and an independent long branch share a run, the join waits for that branch too. The compiler keeps `defer` for joins after branching (the only construct that tolerates untaken branches). It records the extra wait as expected behavior; it is not a defect, because sub-flows and swarms run as separate graph runs with their own `defer` scope. `durability="exit"` costs nothing per superstep. The runtime always sets `recursion_limit` (G-12).
