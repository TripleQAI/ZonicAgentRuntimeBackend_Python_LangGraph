# SP-9: node name constraints

Script: `spikes/test_sp09_node_names.py` (16 names). Each name is added, compiled with a checkpointer, run as the node that invokes a child graph, and checked in the stream namespace.

| Name | Result |
|---|---|
| `agent-1`, `agent_1`, `Agent 1`, `node.with.dots`, `a/b`, Unicode, 300 characters | Accepted; runs; the namespace segment carries the name unchanged |
| `value` (equal to a state key) | Accepted |
| `""` (empty) | Accepted |
| `a:b`, `branch:to:x` | Rejected at `add_node`: `':' is a reserved character` |
| `a\|b` | Rejected at `add_node`: `'\|' is a reserved character` |
| `__start__`, `__end__` | Rejected at `add_node`: reserved |
| `__interrupt__`, `__pregel_push` | Rejected at `compile`: reserved |

**Conclusion:** design Section 6.9 holds, with a wider reserved set than it lists. The escaping rule must cover `:` and `|`, and every name that starts with `__` (LangGraph reserves internal names, and reports some only at compile). The validator rejects empty builder node IDs, because LangGraph accepts them silently. Builder IDs are otherwise used unchanged.
