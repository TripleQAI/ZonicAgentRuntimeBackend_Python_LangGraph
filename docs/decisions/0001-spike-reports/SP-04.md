# SP-4: Langfuse v5 under `propagate_attributes` on an isolated provider

Script: `spikes/test_sp04_langfuse.py` (5 checks, all pass). Langfuse 5.0.4 with `tracer_provider=` its own `TracerProvider` and `span_exporter=` an in-memory exporter; no network.

| Question | Result |
|---|---|
| Parenting | Every span of the run (graphs, nodes, the agent graph invoked in a node, model calls, tools) is one trace under the runtime's root observation |
| Propagated attributes | `user.id` and `session.id` on every span; trace name, tags and metadata set |
| Observation types from `CallbackHandler` | Model calls `generation`, tools `tool`, everything else `chain`. Any chain whose name contains "agent" becomes `agent` (a name heuristic), so `n_agent` is typed `agent` whatever the node really is. |
| Node attribution | `add_node(metadata={"zonic_node_id": ...})` appears as `langfuse.observation.metadata.zonic_node_id` on the node span **and on every model and tool span inside it** |
| A node returning `Command` | The output is recorded as JSON `{graph, update, resume, goto}`, so `update` and `goto` are readable at export |
| `should_export_span` | Drops the agent graph's internal `model` and `tools` wrapper spans |
| `mask_otel_spans` | `OtelSpanPatch(set_attributes=...)` rewrites `langfuse.observation.type` at export from the node metadata |
| Isolation | The global tracer provider stays a `ProxyTracerProvider` |

**Conclusion:** the design holds, with one change. The runtime never trusts the handler's typing; observation types come from the node metadata the compiler attaches. Enrichment happens at export (in the gateway exporter, and through `mask_otel_spans` for the optional Langfuse server exporter), not inside the node. A dropped wrapper span leaves its children pointing at a parent that was not exported, so the gateway exporter must re-parent them to the nearest exported ancestor (P2-08). The fallback (node observations opened by the template) is not needed.
